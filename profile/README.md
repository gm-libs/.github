## 📚 What gm-libs Is

gm-libs, "GM Library" on the organization page, is the library organization of [Webanion](https://github.com/webanion). Webanion builds and runs products. gm-libs holds the reusable code those products share, so a capability is written once, tested once and released once, and every product picks it up as a versioned package. Both are owned and led by [Md Moniruzzaman](https://github.com/geniusmonir).

Each package covers one capability and is named after it, not after the framework it happens to run in. A package works from plain Node.js first, with thin layers for the frameworks Webanion's products use on top, so the same library serves a backend service, a web app and a mobile app without being written three times.

* 🔭 **Currently:** a growing set of libraries covering the foundations a product needs: data access, identity, messaging, documents, background work and user interface.
* 🚚 **Running in production:** Webanion's own products are built on these packages.
* 🌍 **Where we are:** Bangladesh, UTC+6.
* 💬 **Ask us about:** using a library in your own product, or opening one.

## 💻 Stack

**Language and runtime:** TypeScript, Node.js

**Frameworks served:** NestJS, React, Vue, Next.js, Expo

**Data and platform:** PostgreSQL, Redis, Temporal, OpenFGA

**Delivery:** GitHub Actions, versioned releases to a private registry

## 🔒 What Is Public Here

Nothing yet, apart from this page. The libraries are private and are published to a private registry, where access is by invitation. Whether a library opens is decided per library once its API stops moving, and the ones that do will be listed here first.

<br/>

## 🧪 How They Are Built

* 🔁 **One pipeline for every library.** Every repository runs the same checks before anything merges: lint, types, tests, build, and a smoke test of the packed package.
* 🏷 **Every release is a version.** A release is cut by the pipeline, tagged and published as an immutable version. Nothing is published by hand, and a published version never changes.
* 🧫 **Tested against the real thing.** A library that talks to a database or a browser is tested against one, not a mock of one.
